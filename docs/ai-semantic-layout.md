# AI semantic layout on mobile

AI layout is opt-in under Settings → Typesetting → AI layout, with an independent provider, model and reasoning-effort selection. An unavailable model pauses recognition without silently switching providers. API keys stay in secure storage. The settings explain that enabled recognition sends excerpts and candidate formula images to that provider.

Quotations, source attributions, figure captions and numbered or unnumbered subsection headings share one strict-schema request per source batch. Heading candidates are ordinary paragraphs of up to 120 Unicode characters, excluding math, images and footnote roles. Contextual decisions belong to the model; short text alone is not proof of a heading. Existing semantics are protected. Invalid responses receive one correction attempt; duplicate groups and redundant authored-heading labels do not trigger retries. Entirely invalid responses are not cached as empty successes.

Plans use original authored headings and available TOC anchors. Each activated subsection has stable batches with a 5,000-source-character budget. Whole blocks, authored media/caption runs and known quote/attribution groups are indivisible; an oversized group is sent alone. Split batches include one neighboring source group on each side, inside the same subsection, as read-only context. Every annotation must remain entirely within its target batch. Prompt, schema and context overhead are outside the character budget.

Visible batches run first, followed by remaining batches in the visible subsections. There is one active request. Moving inside its subsection keeps it running; replacement work in another subsection preempts it. Unstarted work outside current demand is dropped. Completed batch caches are reusable after returning. The reader no longer automatically processes the next chapter. Preparation and composition use background isolates whose closures do not capture native reader resources.

Visible translation waits until its semantic batches have completed or failed, then proceeds. Page refresh waits for the in-flight translation and active page turns to finish, combines dirty results, and restores the latest source anchor. Recognition failure retains the original layout and permits translation. Leaving the reader cancels work; late results cannot install annotations or promote cache files.

Composition preserves source ranges, inline styles, links and bilingual companions. AI alignment applies only to unified typesetting. Book files are never changed; fixed-layout PDFs are excluded and retain their pure-Dart pipeline. Inline credits are not guessed from translated suffixes.

Cache v4 keys include book identity, chapter source content, provider endpoint, model, reasoning effort, prompt, schema revision and stable batch/context boundaries. Successful empty batches are cached. Network failures and cancellation are not. Persistent storage remains bounded to 512 entries. Font and theme changes reuse recognition. Changing AI configuration clears incompatible overlays and plans; reopening settings or resuming with identical configuration preserves successful results and translations, retrying failed batches only.

## Inline references and formulas

Bibliographic candidates and exact text-formula proposals share the text recognition request with structural groups. Target text is supplied once in canonical `math_texts`; blocks refer to paragraph IDs. Inline annotations preserve source characters, styles and anchors. Formula selection protects links, images, existing math, footnotes, citation spans and complete superscript/subscript groups. Ambiguous and overlapping proposals are rejected; valid siblings survive.

Confirmed references, website links and formulas enter the translation input before translation begins. Protected reference/link markers and formula placeholders must survive exactly once. Existing translations can still display unmarked text; changing inline semantics invalidates only affected blocks. A revision guard rejects translation results produced against an incompatible semantic snapshot. Copy/search uses source text; clicking a rendered formula opens a compact preview with a Copy action.

Image formulas use PNG, JPEG, WebP and GIF originals (GIF first frames are losslessly converted to PNG in a worker), batching at most five distinct images and six MiB of base64 image payload. Equal image bytes deduplicate across resource names. Recognition and self-check share the first request; only locally invalid transcriptions receive conditional review. Missing or duplicate IDs retry only those items. Positive and definitive negative classifications are cached; unreadable or failed-review results retain original images and remain retryable. Captioned figures and fixed pages are excluded. Image-input failures do not suppress text recognition or switch providers.

Mathematics renders with the pure-Flutter `flutter_math_fork` parser/layout into the reader's Canvas pipeline. Source length, nesting, expansion, output dimensions and a 32 MiB session raster budget are bounded. Failed rendering falls back to the original styled text or image. Retained page rasters are not evicted underneath active frames. Inline placement uses mathematical baseline metrics; standalone formulas receive padding and centered layout. Book typography restores source text/images. Authored equation labels take precedence over identical embedded labels; conflicts retain the original image.

Reference markers are numbered per source paragraph, not per page. Their popup lists ordinary footnotes before citations, scrolls to the selected citation and can render note formulas. Website icons are a unified-typesetting presentation feature independent of AI recognition; only HTTP(S) destinations are launched externally. Source text and targets survive copying and translation. Formula previews show recognized mathematics in a content-sized dialog with a Copy action and no title. Original-image resources are retained independently for authored layout and fallback.

Validation includes semantic composition, strict-schema correction, cancellation, per-batch reuse, reasoning/content cache isolation, read-only context, and reader integration tests for same-subsection reuse, preemption, late results, and coordinated translation refresh. Providers are controlled HTTP mocks; live model quality and mobile-device performance require separate verification.
