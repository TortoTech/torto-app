# 桌面 0.7.1 同步遗漏复核

## 基线与结论

对照桌面工作区 `2ab35ce`（产品版本 0.7.1）和 App 当前 `0.7.1+7110` 工作区，即此前部署的 Android 版本码 9110。App 的 Git HEAD 仍为 `1709c32`，已有同步改动尚未提交，所以本次对照的是工作区源码。桌面 `e3c88ed` 之后两次提交主要是 macOS 编译及安装恢复、HTTPS 测试证书，未发现新的跨端 LLM 功能。

此前同步不完整。主要遗漏是请求契约、模型能力路由和配置生命周期；提供商数量及功能入口对齐，不能证明这些行为已对齐。本轮只复核与记录，没有改业务代码、构建或部署，也没有模型/搜索服务调用。

以下“确认遗漏”均有两端源码依据；“已知缩减”是此前明确采用的简化实现，应列入后续同步范围，不能继续描述为完整桌面等价。

## 一、优先修正的请求与提示词

### A1：精简 JSON 请求协议没有迁移〔P0，确认遗漏〕

桌面 `apps/desktop/src/plugins/semantic_layout/wire.rs:1` 定义字段与枚举映射，提供 encode/decode、schema 转换、仅改写代码标识符的提示词转换。例：`groups → g`、`body → d`、`kind → k`、`results → r`、`image_id → ii`。源字符串、ID、LaTeX 不变。

桌面 `semantic_layout.rs:1338` 同时应用精简提示词、精简输入和精简 schema，随后还原输出。`semantic_layout/formulas/batch.rs:135` 也使用这套协议。

App `semantic_layout_service.dart:311`、`semantic_layout_contract.dart:3`、`formula_image_service.dart:127` 仍发送完整字段名及 schema；没有对应 wire 编解码模块。只做了按当前窗口选择提示词章节，没有完成 0.7.0 的请求体积优化。

实施要求：新增纯 Dart 编解码层，覆盖语义排版和公式图片两条路径；同时迁移 schema 和指令，解码后继续现有校验。不得缩写原文、LaTeX、ID 或任意普通字符串；缓存应基于明确协议版本及 canonical 数据。

验收：请求捕获确认实际 payload/schema 为短字段，枚举仅在指定字段转换；中英文、markup、LaTeX、重复原文和源偏移往返无损。对相同窗口记录请求字节数，不能用静态 prompt 长度代替实际请求验证。

### A2：语义提示词与窗口边界没有完整对齐〔P0，确认遗漏〕

归一化换行后直接比较资源：App `assets/ai/semantic_layout.md` 为 6648 字符，桌面 `semantic_layout/prompt.md` 为 6566 字符。差异主要是：

- 桌面标题说明限定编号标题、独立章节编号；App 仍含普通文字标题和问答式标题说明。App 候选过滤已改为编号/章节前缀，但指令没有同步。
- 桌面允许连续分组接触目标窗口并利用相邻上下文；App 要求整组完全位于目标窗口。`lib/core/semantic_layout/semantic_layout.dart:263` 及重试反馈也采用后者，不只是提示词文本差异。可能漏掉窗口边缘的引用正文及其署名关联。

实施要求：先对齐上下文 ownership、分组去重和验证边界，再对齐 prompt。不能只复制“touch the target range”，否则本地校验仍会丢弃模型结果。

### A3：翻译 0.7.1 契约与恢复机制缺项〔P0，确认遗漏〕

桌面 `plugins/translation.rs:17` 使用短 `t-*` 标签，并在读取时归一化旧 `torto-*`。脚注、网址及文献引用具有身份契约。`plugins/ai.rs:909` 使用固定响应 schema、数字段落键、可容错的术语字段 `g`；验证失败会把具体错误加入后续请求，并拒绝未请求的正文键（`ai.rs:1056`）。

App `TranslationMarkupCodec` 仍使用长标签；将引用与网址隐藏为 `torto-protected`，脚注结构没有桌面相同的 ID 契约。`openai_compatible_client.dart:163` 未传翻译 schema，重试重复原请求；`_translationObject` 只检查请求键是否有非空文字，没有拒绝额外正文键。已有公式索引范围保护和失效译文重试不能替代这些契约。

专家翻译的核心术语存储已迁移，但桌面将固定提取规则置于 system、已有术语数据置于 user，并强调同形异义、变形和有意义缩写。App 将这些内容拼在 system 中，规则也有所简化。

实施要求：迁移新版输出/验证/反馈及术语规则；为 App 的源结构建立等价身份映射。保留旧缓存读取兼容，不清空既有译文，不把所有标签做无条件文本替换。引用内容是否翻译及身份如何保留需要与桌面一起验证。

用户此前撤回的“翻译默认不思考”设置调整不作为本轮遗漏重新提出。

## 二、搜索设置与工具链

### B1：搜索选择 UI 仍与桌面不同〔P0，确认遗漏〕

桌面 `settings/egui_view.rs:1382` 使用一个“搜索提供商”选择框：所选对话模型支持时显示“官方服务”，另外提供 Tavily、Brave、Exa、SearXNG。搜索关闭时不显示额外配置；官方模式不显示外部服务地址/密钥。

App `assistant_settings_page.dart:128` 仍同时显示“优先使用提供商官方搜索”开关和外部服务配置，不按模型能力控制。这会让用户无法直接判断配置的外部服务是否实际生效。

实施要求：迁移 Auto/Native/External 状态及模型选择迁移；统一为一个选择框，按模式展示配置。四个外部类型和三类固定默认地址已经对齐，不应再次替换为自定义接口。

### B2：各服务独立配置和切换恢复缺失〔P0，确认遗漏〕

桌面 `web_search.rs:89` 保存服务列表、选中服务和模型选择身份；`select_service` 复用已有服务记录，切换回来恢复端点和密钥。该行为还有 `web_search.rs:910` 附近的配置恢复测试。

App `assistant_settings.dart:25` 只有一份端点/密钥，安全存储只有一个固定 key；切换服务时重设端点并清空密钥。此前这避免了串用凭据，但没有实现桌面的恢复行为。

实施要求：按服务身份分别保存端点及安全存储密钥，切换只更改选择。迁移旧单服务配置到对应记录，不能丢失已保存密钥。新选中的服务填默认端点，已配置服务恢复自己的端点。SearXNG 没有统一默认实例地址。

### B3：官方搜索能力与失败回退缺失〔P0，确认遗漏〕

桌面 `web_search.rs:302` 的模型能力路由覆盖 OpenAI、Anthropic、符合条件的 Gemini、xAI、OpenRouter、Z.ai；另外通过官方 REST 服务支持 Moonshot 和 Mistral（`web_search.rs:430`）。OpenAI/Gemini 有模型限制，Custom 不自动调用模型官方搜索。

App `chat_assistant.dart:193` 只按提供商类型选择 OpenAI、Anthropic、Gemini，不判断模型；缺少其余路由。不能把“15 个 LLM 提供商都有聊天适配”等同于“15 个都迁移了联网搜索”。

桌面识别明确的“不支持官方搜索”错误，缓存能力失效一小时，并仅在用户已配置外部服务时回退（`ai.rs:370`、`web_search.rs:343`）。401、429、超时不会被当成能力失效。App transport 的搜索异常只暴露 HTTP 状态码，ChatAssistant 没有这条回退链。

实施要求：迁移可测试的能力矩阵、路由、错误分类及缓存；保留明确的来源信息。先恢复完整协议错误以支持分类，不用任何错误触发隐式备用服务。

### B4：工具与历史轮数设置缺失〔P1，确认遗漏〕

桌面提供工具轮数 1–24（默认 24）、历史轮数 1–50（默认 10）、对话思考等级；见 `plugins/mod.rs:63` 和 `settings/egui_view.rs:1335`。

App 固定三个工具步骤、24000 字符历史预算，UI 不提供相应设置。网页检索每回合三次、单次最多五条结果是另外的限制，不能把它与整个对话工具轮数混为一谈。

实施要求：分别配置工具循环、历史轮数及字符总预算；保留独立网页请求预算和取消/超时。模型切换时同步能力选项，避免界面提供实际无效的思考等级。

## 四、已经迁移或无需重复迁移

- 公式图片三份提示词正文逐字相同：base 581 字符、transcribe 440、verify 494；真正缺项是请求 wire，不能笼统报告“所有 prompt 都没同步”。
- system 指令保留、Custom 默认 prompt JSON、结构化输出的格式回退和 JSON 恢复已有实现；后续应补完整模型能力与任务契约，而非重写这些已验证路径。
- 专家翻译的按书籍/语言术语存储、有限提取、冲突校验和 best-effort 存储已实现；规则和请求组织仍有上文差异。
- 小节边界、目录 fragment、标题排除、列表前置段落、停靠滑动、图片按屏幕精度加载已完成相应移动端实现；不能因本轮查出其他遗漏而全量重做。
- 桌面 Windows/macOS 标题栏、GPU 窗口最小化及安装器恢复不属于 Android 同步范围。已撤回的翻译默认值需求不重新引入。

## 五、建议实施顺序与完成标准

1. **请求契约**：A1–A3。先迁移编解码及兼容读取，随后更新 prompt/schema/验证反馈。每项都捕获实际请求和响应，迁移桌面回归样例；已有译文不被清空。
2. **搜索链路**：B1–B4。先按模型及模式决定真实路由，再迁移 UI、独立服务存储、恢复、能力失败与配置好的备用服务。覆盖每个官方分支、模型切换、关闭状态、401/429/超时、备用服务未配置等情况；不靠真实收费请求证明逻辑正确。
3. **助手与 PDF**：明确工具、读写权限及确认 UI，补当前上下文/正文、书内引用与页面图像，再迁移 PDF 发现代理及呈现能力。批注写入和正文改写必须保留桌面的用户确认与明确请求约束。
4. **阅读边界与呈现**：引用规则、语义边框、预览控件；最后单独决定受管 APK 下载和 OCR 的范围。

同步清单应逐项记录“源码契约、请求/交互证据、回归样例、未实现边界”，并绑定部署版本。此前 511 项完整回归和后续 18 项转场测试证明已实现路径可通过测试，未覆盖到的桌面能力不能因此被标为完成。本次复核没有新增运行测试，以上源码差异也不代表已经测量实际模型成本或识别准确率。
