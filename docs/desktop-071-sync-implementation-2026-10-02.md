# 移动端 0.7.1 同步实施记录

App 已从 `1709c32` 的 `0.6.2+6200` 同步桌面 `e3c88ed` 的主要新增能力，工作区版本为 `0.7.1+7100`。专注模式改为按小节导航，标题保留正常显示。改动尚未提交、推送、发布或安装到手机。

## 专注阅读与目录

原始目录的 href 和 fragment 定义阅读小节。一个小节对应一张逻辑页，可以超过一屏；上下滚动不会跨小节，左右滑动切换小节。重复目录锚点去重，坏锚点不丢内容，纯标题前导区并入下一小节。没有有效目录边界时整 spine section 回退为一个小节。原始 PDF 和固定版式沿用原有阅读路径。

标题的几何定位与正文激活范围已分开，标题不参与淡化、激活或正文点击命中。恢复正文起点时保留前面的标题。列表及其前置自然段落整体关联，超高列表按根项划分激活部分，嵌套项随根项移动。源锚点用于重排、模式切换和重开，近期回访状态保留八个小节。

实现复用了 `PageLayout` 的显示列表、文字测量与分页生命周期，通过 `ReadingUnitIndex` 和 `focusId` 表达逻辑页，没有再引入一套独立的 `FocusSectionLayout`。这样继续使用既有链接、选择和源偏移映射。目录行保留 href，定位及当前目录标记支持 fragment。AI 排版和翻译从视口范围收集需求，避免把长小节作为整章请求。

## 内容排版与译文兼容

显式 figure 中的普通段落图注得到保留，独立列表尾注保留各自定义和锚点，纯图片及带编号公式图片不再充当引用推断证据。统一版式加粗图表编号；分开的表编号和标题可以共享首行基线并自然换行，各自源节点、链接和选择映射仍保留。脚注标记增加横向间距。

按句分段支持冒号，并保护时刻、比例、URL、协议前缀及配对标点。AI 标题候选限制为编号或章节前缀。常见作者年份引用，包括多个作品和年份，先在本地识别；数字括号引用要求文献提示，避免混淆数组、矩阵等表示。

公式占位符解析显式检查索引。原文内联识别发生变化时，只移除不兼容的译文段，保留原文并允许重新翻译；有效缓存继续使用。此轮不触发全书重译，不改书籍身份、标注或 WebDAV 进度协议。

## AI 提供商与专家翻译

提供商类型与桌面一致，共十五类。Anthropic、Gemini、Ollama 使用相应原生协议，其余使用兼容接口；模型列表和分页也按提供商处理。结构化输出失败时只针对输出格式相关错误退回更宽松格式，原有任务 system 指令始终保留。JSON 恢复处理围栏、前导文字和字符串外的尾逗号。

提供商设置支持搜索，内置名称固定，新提供商不再预填模型。AI 排版缺省不思考；已有明确保存的偏好继续读取。翻译、语义识别、公式识别、阅读助手及 PDF 识别使用同一请求层。

专家翻译缺省关闭，通过书籍和目标语言隔离术语。每批最多新增八条，存储最多两千条，提示词按预算选择匹配项；源词和译词必须出现在同一成功翻译段落中，冲突不会覆盖已有术语。无效元数据或存储失败不使译文失败。切换专家模式影响后续请求，不自动重译已有文本。术语目前保存在本机，没有扩展 WebDAV 同步对象。

## 阅读助手与联网搜索

阅读器头部增加助手入口，可以围绕当前激活内容对话，或开启全书检索。书籍和正文块的会话分别保存。回答支持真实 SSE 或 JSONL 增量输出、停止、重试，以及可选择的正文和可点击的引用链接。失败或取消的半成品不会写成已完成会话。

OpenAI 官方搜索使用 Responses，Anthropic 和 Gemini 使用各自搜索工具；最初 APK 的外部搜索支持 Tavily、Brave、Serper 或自定义接口，后续工作区已纠正为桌面一致的 Tavily、Brave、Exa、SearXNG，参见[后续修改与交互方案](mobile-071-followup-plan-2026-10-02.md)。全书及第三方检索最多三个工具步骤，重复或不可用工具请求会拒绝执行。官方服务的内部搜索行为仍受其 API 约束。搜索缺省关闭，搜索密钥使用安全存储。

助手和 PDF 识别模型在“设置 → 阅读助手”选择；未单独选择时使用现有翻译模型。对话历史和当前摘录有独立大小限制。当前 PDF 原始页没有新增 OCR 或全文检索能力；不能因此承诺扫描 PDF 的正文问答效果。

## PDF 识别与更新来源

PDF 识别入口可以按需检查页面，保存草稿，识别元数据、目录候选和特殊页。目录目标必须经过单独的实际目标页图像检查，无法确认的条目不进入已核验列表。识别结果在 App 中查看后应用，写入现有派生元数据格式，重开书籍仍可使用。未核验草稿不会成为目录。

识别默认最多检查三十二个不同物理页、八轮发现请求，每次最多四张预览；目标页核验同样计入页面预算。较大或复杂 PDF 可能得到部分目录或需要重试，不能把模型确认等同于人工正确率验证。页面仍由纯 Dart PDF 管线处理，识别预览独立缩放，不改变阅读渲染器。

更新设置增加自动、GitHub 和 Gitee 三种来源。Gitee 必须提供与版本、Android arm64 APK 及附件一致的完成清单。镜像脚本从桌面适配，检查附件散列、大小和远端上传结果后才发布清单；实际镜像运行需要 `TortoTech/torto-app` 的 Gitee 仓库及 GitHub Actions 的 `GITEE_TOKEN` secret。此轮没有修改远端配置或触发发布。

App 继续打开发布页供用户下载安装，没有新增托管 APK 下载或自动安装流程。完成清单不等于 App 对浏览器下载文件做了一次额外散列验证。
