# 移动端搜索设置、图片清晰度与专注滑动

## 当前结论与范围

本文保留调研证据与设计依据。搜索设置、图片清晰度和专注滑动随后已实施，具体结果见[实施记录](mobile-071-followup-implementation-2026-10-02.md)。

## 搜索设置：已修正

对齐桌面 `plugins/web_search.rs` 的可选列表：Tavily、Brave Search、Exa、SearXNG。删除 Serper 和 Custom，不提供任意请求模板、字段映射或自定义 HTTP 类型。

打开设置时显示有效服务地址；切换服务时填入该服务默认地址，清除上一服务的密钥，避免带入错误凭据。Tavily、Brave、Exa 有固定默认地址；SearXNG 与桌面一样没有统一地址，填写用户所用实例的搜索地址，并要求实例支持 JSON。

保留服务地址字段，供现有提供商的代理或 SearXNG 实例使用。旧 Serper/Custom 设置回退到 Tavily，不把旧端点和凭据带入新服务。已有 Tavily/Brave 配置保持有效。此轮不改模型原生搜索的优先开关。

补齐 Exa 的 POST、API key 和 highlights 适配，以及 SearXNG 的 JSON GET；统一结果片段上限和来源链接检查。

验证：搜索设置与 AI 相关测试合计 18 项通过，包括服务切换地址、旧配置迁移、Exa 和 SearXNG 请求及片段。请求协议参考 [Exa](https://exa.ai/docs/reference/search) 和 [SearXNG](https://docs.searxng.org/dev/search_api.html)。没有真实搜索请求或付费调用。

## 图片：清晰度下降的证据

`ReaderController._decodeSectionImages` 用整章新图片数量 N 分摊 24 MiB 解码预算，将每张最长边限制为：

`min(2048, floor(sqrt(24 * 1024 * 1024 / (4 * N))))`

示例：20 张约 560 px，50 张约 354 px，100 张约 250 px。手机当前显示模式为 1080×2400、密度 420；整幅宽图只有几百像素时会被放大，图中文字尤其容易模糊。预算只依据本次新增图片数量，不依据图片的原始尺寸、实际显示区域或设备像素比，清晰度还可能随缓存命中情况变化。

对比同步前的 `HEAD`，该解码策略未被本次 0.7.1 同步修改。它是既有问题；不能把用户正在看的具体图片全部归因于它，因为还没有问题书籍及图像样本。

各格式代码检查结果：

| 格式 | 资源路径 | 风险 |
| --- | --- | --- |
| EPUB | 从 ZIP 提取原图字节，再进入统一解码 | 多图章节会显著降采样；源文件未重压缩 |
| MOBI/AZW/AZW3 | 转为 DirectBookSource，读取原始图片资源 | 同一章节预算问题；格式本身的低清图片无法恢复细节 |
| FB2/FBZ | 解码嵌入的 base64 图片，交给 DirectBookSource | 同一章节预算问题 |
| CBZ | 提取原图，通常每幅图一个 section | 通常不受多图分摊影响，但仍有最长边 2048 上限 |
| CHM/HTML | 原始资源进入统一解码 | 多图章节同样受影响 |
| PDF | 每物理页经纯 Dart 管线栅格化；缓存按页及分辨率区分 | 通常每页一幅图，仍有 2048 上限；需要独立检查小字及放大需求 |
| TXT | 没有内嵌图片 | 不涉及此路径 |

页面及行内图片绘制使用 `drawImageRect`，没有显式配置采样质量。正文通过 `CustomPaint` 直接绘制，并非先把整页压成低分辨率截图。PDF 识别用的 1000 px 预览独立于阅读资源，不会替换阅读图片。

### 建议修复顺序

1. 将原始尺寸元数据与解码纹理分开。排版始终使用原始宽高比及源尺寸，避免提升纹理清晰度时改变布局。
2. 不再按整章图片数降低所有图片的精度。按显示区域和设备像素比计算所需像素，优先解码视口及相邻区域；离屏纹理通过实际占用字节的缓存预算淘汰。
3. 放大查看时按所需尺寸重新解码原图；高质量资源与预览资源使用不同缓存键，不能把低清缓存当作最终资源。不会对低清原图承诺恢复细节。
4. 对页面和行内图片明确缩放采样策略。采样改善只能减轻缩放伪影，不能替代足够的源像素。
5. PDF 继续纯 Dart 渲染；根据屏幕实际需求请求栅格尺寸，并沿用带分辨率的磁盘缓存。保留识别预览的独立预算。

验证应使用含大量图片的 EPUB，以及 FB2/MOBI/CBZ/PDF 样本。记录原始、解码、显示物理尺寸和缓存质量，比较图中文字及细线，同时检查打开耗时、连续翻页和峰值内存。现阶段是路径检查，尚未完成这些真实样本及清晰度验证。

## 专注滑动：设计方案

### 桌面与手机的实质差异

桌面滚轮先积累方向和阈值，再执行焦点导航；普通内容块切换后平滑定位到中央阅读区域。长内容块先在块内逐段前进，抵达其边缘后才切换块。桌面使用 160–360 ms 的距离相关缓入缓出动画，图像与图注有独立停靠逻辑。

手机当前垂直拖动直接修改整小节 offset，松手后执行 `FrictionSimulation` 自由惯性；激活内容由视口 20% 位置推断。点击内容也仅激活而没有定位动画。这解释了为什么数据分页已经按小节同步，阅读节奏仍与桌面不同。

### 默认交互

| 操作 | 建议行为 |
| --- | --- |
| 向上/向下滑 | 短内容块切换下一/上一激活块，平滑停靠；不以惯性跳过多个块 |
| 长段落、表格、列表、长图 | 先在当前块内移动一个阅读窗口，保留可读重叠；到底/顶后下一次手势才换块 |
| 左右滑 | 切换下一/上一小节；两个小节表面同时平移，保留各小节访问位置 |
| 小节首尾继续竖滑 | 边界反馈，不跨小节；符合用户已明确的左右切小节要求 |
| 点击正文 | 激活该块并平滑定位；正在运动时从当前视觉位置重新定位 |
| 点击标题 | 保持标题正常显示，按现有行为显示/隐藏工具栏，不激活正文 |
| 链接、脚注、文字选择 | 优先执行对应操作；选择和拖动手柄时禁用阅读导航 |

“每页一个小节”保持不变。段落、引用、列表、图表是小节内的激活单位，不能把这些单位重新分页为横向页面。按句分段开关只影响小节内激活粒度。

### 手势与动画

- 超过触摸容差后锁定横向或纵向，一次手势只驱动一个方向，斜滑不会同时滚动和切小节。
- 普通块采用小幅跟手预览，松手超过距离或速度阈值后完成一个导航步骤，否则回到原停靠点。初始距离阈值建议 36 dp，最终用真机调整。
- 长块优先保留跟手可读性，松手停靠到当前块的合法阅读位置；一次快速滑动最多推进一个阅读窗口，不执行整小节自由惯性。
- 阅读窗口初始参考桌面中央 240 dp；普通块用虚拟最小容器定位，长块按中央阅读窗口推进。图像完整可见时先定位图片，再定位图注；长图先读到图底。
- 停靠动画参考桌面：距离 / 1000 dp/s，时长限制 160–360 ms，缓入缓出。再次触摸可打断；连续输入以目标及实际到达状态处理，禁止尚未抵达长块底部就越界。
- 顶部、尾部增加适度留白，让首末内容能停靠；标题不属于激活绘制范围，但小节首次进入时必须保留标题可见，不能因居中而隐藏标题。

### 实现边界

在 `FocusReadingState` 上增加明确的导航目标：相邻块、块内位置、边界，以及当前运动/目标源锚点。将停靠与超高块算法提取为独立策略；`ReaderPage` 负责手势识别和动画，不再决定激活块。动画过程中不调用 `activateVisible` 重选内容。

`ReaderController` 统一调度激活、进度、译文和语义布局。布局刷新时用源锚点与屏幕相对位置恢复，而非旧像素 offset；移动过程中缓冲 AI 重排，稳定后应用。图片加载不能改变原始布局尺寸。

横向过渡与纵向停靠分别管理状态；离开小节、打开助手/脚注、切换模式或开始选择时取消运动并保存稳定锚点。先完成目标布局、图像引用和激活状态，再在同一帧提交，避免闪现新小节首图。

### 验收

短段落连续滑动每次仅推进一块；长段落和长列表能读完全部内容后才换块。图、图注与长图的停靠顺序可逆。标题不变暗、不抢正文激活。横竖斜滑、反向中断、快速重复滑动、首尾边界、字号调整、翻译重排及退出重进均保持源位置。

真机检查运动跟手程度、帧时间、低清图升级、图像闪屏与内存；自动测试覆盖导航目标和手势互斥。此方案尚未实现，不把先前视觉截图当作滑动体验验收。
