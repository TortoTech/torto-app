# Torto App 同步桌面 0.7.1：调研与修改方案

日期：2026-10-02。本文是实施设计，未修改业务代码，未运行模型请求、构建或部署。

实施记录见 [移动端 0.7.1 同步实施记录](desktop-071-sync-implementation-2026-10-02.md)。下文保留调研时的设计基线。

## 1. 对照基线与结论

- 桌面：`torto`，`e3c88ed`，workspace version `0.7.1`。
- App：`torto-app`，`1709c32`，pubspec version `0.6.2+6200`。
- 两个仓库调研开始时工作区均干净。
- App 已有 0.6.2 排版同步、AI 语义排版、文内引用候选识别、公式识别、按句分段、统计和云同步；见 `desktop-062-parity.md`。不能把桌面新增功能名称直接当成 App 完全缺失的能力。
- 新增同步以桌面 `v0.6.2..v0.7.1` 的源码和发布说明为依据，同时补齐此前未移植的小节导航。移动端是纯 Dart/Flutter 实现，需要迁移语义和协议，不能直接 cherry-pick Rust 提交。

最优先改动：专注模式从“多个语义块填满一张物理页”改为“一张逻辑页承载一个小节”。左右滑动切换小节，小节可以高于屏幕；标题参与排版与定位，但不参与默认激活效果。

## 2. 专注模式：已核实的差异

| 项目 | 桌面实现 | App 当前实现 | 设计结果 |
| --- | --- | --- | --- |
| 横向导航 | ReaderSession 的 reading unit，相邻小节导航 | `nextPage/prevPage` 按 `pageIndex` 移动，页末才跨 spine | 专注模式增加独立的小节导航；普通阅读继续物理翻页 |
| 小节范围 | TOC href/fragment 解析到源锚点，去重；无边界时整 section 回退 | AI 批次有 subsection，但没有阅读小节索引 | 新建纯 Dart reading-unit 索引，独立于 AI 批次和屏幕高度 |
| 仅标题的前导区 | `build_reading_units` 合并到下一小节；有图/表的前导区保留 | 标题附在后续正文单元；尾部标题也可成为单元 | 沿用桌面规则，保留正文和插图，不生成多余标题页 |
| 垂直范围 | `current_reading_unit_pages` 组合成滚动布局 | paginator 把完整短块拼页，超高块单独滚动 | 一个小节的连续垂直内容，屏幕只是视口 |
| 标题激活 | `rebuild_focus_units` 跳过 heading；首部标题可参与几何定位，但不进入 paint ranges | heading 和正文共同进入 unit bounds，UI 按整个 bounds 淡化/强调 | 分开定位、命中、绘制范围；标题保持正常显示 |
| 目录 | fragment 精度 | TocEntry 有 href，但 TocViewItem 丢失 href；UI 调用 `goToSection` | 保留 href/anchor，按小节和源锚点跳转及标记当前目录项 |
| 列表 | 前置自然段落与列表组合；超高列表拆子块，嵌套项保留 | list root 与 descendants 组合，前置正文、同级列表项未完整对齐 | 迁移桌面 0.7.0 列表规则 |

- 桌面 `apps/desktop/src/reader/mod.rs`：`current_scroll_layout`、`rebuild_focus_units`、`focus_unit_geometry_ranges`、`focus_block_paint_ranges`。

## 3. 建议的移动端交互

“一页一个小节”指逻辑页，不要求把整个小节压缩进一屏，也不把每个段落变成一页。

- 左滑进入下一小节，右滑进入上一小节，不停留在同一小节的物理分页上。
- 上下拖动滚动当前小节，保留惯性；到顶或到底后不自动跨小节。短小节无需滚动。
- 单击正文语义块激活；单击已激活块或空白显示阅读控制。链接、脚注、引用、公式预览先处理。
- 进入新小节默认激活第一个可激活正文块；回访小节恢复已保存的源锚点、激活块和滚动位置。未访问过的上一小节从末尾进入，保持反向阅读连续性。
- 移动端建议滚动停稳后以视口内的正文块更新当前激活块，避免长小节滚远后仍强调屏外内容；该项是移动端适配设计，不声称是桌面手势的原样移植。
- 标题默认正常显示，不成为自动激活候选，点击标题不激活后面的正文，也不出现正文激活底色、侧标或非激活蒙层。标题仍可选择复制，标题内链接仍可点击。此轮不新增标题激活设置。
- 按句分段仍只改变语义块内部排版，不增加小节、段落激活步骤或源字符偏移。
- 控件文案变为“上一小节 / 下一小节”；进度展示采用小节位置与原文定位，不能拿逻辑页数直接计算整书完成比例。
- 原始 PDF、固定版式继续使用既有阅读路径。PDF 目录识别可单独同步，不以此轮专注模式改造为由启用固定 PDF 专注排版。

## 4. 小节边界与数据结构

建议新增 `lib/core/reading/reading_units.dart`：

- `ReadingUnitId`：书籍内稳定标识，来自原始 spine 与边界源锚点；不使用 pageIndex、标题字符串或翻译后文本。
- `ReadingUnit`：起止源位置、原始块/片段范围、对应 TOC id；模型预留多个 spine 片段，但首轮按桌面可重排书籍的边界规则实施。
- `ReadingUnitIndex`：相邻小节、anchor → unit、TOC → unit 的查询。

构建顺序：解析原始 TOC href/fragment → 映射 Section anchors → 按原文顺序排序并去重 → 建立连续范围 → 将仅标题/分隔的前导范围折入后续小节。带正文、图或表的章前内容独立保留。无有效目录边界时整 spine section 作为一个小节，空 section 跳过；坏锚点不能造成内容消失。

首轮不把所有 H1/H2 或 AI 新识别标题直接当作切页边界。桌面的小节导航以原始目录锚点为依据；App 当前 AI batching 还使用 heading 分界，两者不能直接共用。后续若希望无目录书籍也按标题细分，可另加明确回退规则。

小节索引在原始解析层建立，翻译/按句分段/AI 排版只映射展示，不重写原始小节身份。目录更新（例如 PDF 识别结果）按版本重建索引后，以当前源锚点重定位。

## 5. 布局、激活与状态修改

### 布局路径

新增专注用 `FocusSectionLayout`，包含小节内容高度、显示片段、语义块几何及源映射。普通分页路径保持原有职责。可复用文字测量、优化断行、公式和 PageItem；不要简单把 `_Paginator.endFocusUnit` 改成每块 advance，那会变成“一段一页”。

一个小节可能很长，逻辑页不等于巨型单次 Canvas 或一个巨大 Paragraph。按语义片段保留布局，只绘制视口及少量邻域；测量/排版沿用后台调度和取消机制。缓存按实际资源体积与邻近小节有界管理，避免当前“32 个 PageLayout”变成缓存 32 个完整长章。

### 激活模型

`FocusUnitLayout` 分开表达：

- geometry/entry ranges：进入和滚动定位，可包含首部标题。
- activation/hit ranges：正文、列表、图表、引用的有效区域，排除标题。
- paint ranges：激活和淡化实际绘制区域，排除标题；译文绑定源块。

因此标题不再因为跟随正文而继承整个矩形蒙层。引用保留原有背景，公式块和图片用边框，图注/表注与所属内容一起处理。复杂块不能统一用覆盖正文与留白的全宽矩形代替桌面语义绘制。

列表先形成“前置普通段落 + 连续同级列表及嵌套项”的语义组。能够放入视口时整体激活；超高时按前导段落、根项等子块导航/强调，嵌套项跟随根项。窗口改变时按 anchor 恢复子块，不依赖旧索引。

### Controller 与状态

- 增加 `nextReadingUnit/previousReadingUnit`、相邻小节预览准备和提交。手势、控制按钮、目录、搜索、标注跳转统一经过导航适配层。
- 将普通 `pageIndex` 与专注 `unitId + scrollAnchor + activeAnchor` 分开，避免污染普通分页缓存与恢复路径。
- `FocusReadingState` 以稳定 unitId 和源锚点保存状态，像素 offset 只用于同一布局版本内的快速回访。
- 横滑预览与最终提交必须指向同一小节；预览不能提前写进度，准备失败留在原小节，快速连续滑动拒绝旧异步结果。
- 字号、旋转、句分段、翻译更新前记录视口锚点和相对位置，重新排版后恢复；只改变激活不得重新排版。
- 现有 `_queueVisibleTranslation` 从 `currentPage.items` 收集节点。改为整小节后必须按视口源范围取可见需求，不能把整小节当“可见页”一次请求全部内容。
- AI 排版和翻译共享可见源范围及小节身份；同一范围内滚动不取消重启已有任务，跨小节/配置或语义版本变化才失效。
- 持久化与 WebDAV 仍以 canonical SourceAnchor/Locator 为权威；旧 pageIndex 仅作回退。阅读统计和 totalProgression 需要适配长小节内位置，不能始终使用第一屏 progression。

主要修改文件：`reader_controller.dart`、`focus_reading_state.dart`、`reader_page.dart`、`toc_items.dart`、`toc_drawer.dart`、`layout_types.dart`、`layout_engine.dart`、`focus_layout.dart`；必要时扩展 painter，补充独立 reading/layout 文件以控制现有大文件复杂度。

## 7. 数据兼容与实施顺序

1. A：先小节索引与精确目录定位，再接专注连续布局、标题绘制与手势，最后打通进度、重排与调度。
2. B：使用同一组输入对照桌面结果，补内容修复与本地引用识别；排版协议变化精确失效受影响缓存。
3. C：建设统一 provider/transport，迁移现有翻译与语义识别调用，保证旧配置继续能用。
4. D、E：在 C 基础上分别补专家翻译和 PDF 工具识别。
5. F：建设阅读对话及联网搜索完整链路。
6. G：移动发布与更新来源单独实施，最终按实际完成范围编写版本说明。

保留书籍 id、源锚点、标注和历史统计协议。旧专注设置继续有效，不新增第二种专注模式。新布局不删除进度或已有译文；翻译模式/协议版本需要明确缓存签名与兼容读取。

术语先遵循桌面的本地按书籍/语言存储契约；不擅自向现有 WebDAV v1 添一个未约定的同步对象。若要求跨端术语同步，再设计双端格式、冲突与迁移。PDF 草稿同样与验证后目录分开，未验证结果不能发布成可导航目录。

## 8. 验收与验证计划

A 的最低验收标准：

- 同一 XHTML 内含多个 TOC fragment 时，左右一次只跨一个小节；长小节内多次上下滚动都不改变小节。
- 嵌套目录、重复/无效锚点、无目录、空章节、章前插图、仅标题前导区均不漏内容、不产生意外空页。
- 标题不随正文淡化或出现激活效果，标题内链接及选择复制可用，正文仍能正常激活。
- 列表、图注、表注、引用署名和双语伴随文本归属正确；长块可完整阅读和反向进入。
- 目录直接定位小节/fragment；搜索、高亮、内部链接跳转落到正确小节和块。
- 模式切换、重开、字号/旋转、翻译到达及按句分段保持源位置；预览不写进度，旧异步任务不能覆盖新小节。
- 长小节滚动不会请求整章翻译，不反复取消同范围工作；普通阅读和固定 PDF 无回归。

测试扩展现有 `focus_layout_test.dart`、`reader_focus_gesture_test.dart`、`reader_focus_progress_test.dart`、`reader_toc_test.dart`、`reader_translation_navigation_test.dart`、`reader_semantic_scheduling_test.dart`，并新增 reading-unit 纯逻辑测试。
